# 1900—2026 历史国界：首轮数据来源核查

核查日期：2026-10-14。用户选择：优先完整考证与准确性。

## 当前结论

已建立可运行地图和可追溯数据台账，但**尚未完成1900—2026年全球国界的独立历史考证**。不能把现有网站作为完整精确成品。当前640条记录全部保持 `unreviewed`；技术验证通过不等于历史真实性已经验证。

最重要的发现：CShapes适合作为国家层面的起始资料，但其自身编码规则不满足全量逐日、细粒度、法理与实控双重精确复原。

## 说明文档中的精度限制

以下引文来自链接PDF的相应页；它是2018版文档，具体记录仍需单独核查。

1. 第3页：`we used the first of January, or the first of the month as a default`。部分缺少精确日期的记录用年初／月初占位。**日期字符串完整不表示日期已精确考证**。
2. 第3页：`we only code de jure changes in territory and sovereignty`，并以条约签署日作为编码示例。**签署、批准、生效、交接、国际承认等日期必须分开建模**。
3. 第4页：排除 `Territorial changes below 10’000 sqkm`。面积较小的边界调整不一定收录。
4. 第4页：排除多种未获承认且后来撤销的领土交换，以及战后立即逆转的战争期间变化。**不能用作逐日军事占领图**。
5. 第4页：无历史变化证据时回溯现代边界；部分相互冲突地图选择更接近现今边界者。**早期轮廓可能是回溯假定，并非同期史料测绘**。
6. 第5页：`changes may also stem from changes in the capital city, or other attributes`。**记录数不是国界变化次数**。

实际GeoJSON只有名称、面积、首都、GW代码和日期等字段，缺少文档中的 `status`、`ruledby`、`b_def`。因此网站不根据名称自动判定独立／殖民／保护国，也不绘制伪造的宗主国颜色。

## 核查台账和可追溯性

- `public/data/provenance.json` 固定原始文件SHA-256、下载日期、许可和转换方式。
- `public/data/research-register.json` 保存每条记录的原始要素行号、稳定ID、几何哈希、来源日期、核查状态与空证据数组。
- 边界原始坐标精度全部保留；仅调整环方向适配D3，没有自行推测或平滑历史国界。
- 对各实体有效期间自动检查重叠与缺口。发现14处间隔，标为 `gap-requires-context`，不自动填补：部分国家确实曾被吞并或中断独立。
- 1900—2019每年年末有来源记录，但仍属于“未独立复核”；2020—2026为“缺失”。
- 浏览器中的地区卡片可查看历次记录、原始行号、同一几何版本、实际有效日期。

## 精确版数据标准

每条新增或修正边界应具备：

1. 实体ID、当时正式名称与别名，政体名称独立存放；前身／后继关系不能只靠名称推断。
2. 边界类型：法理、实际控制、行政、声索、争议；允许同一地区多层重叠，不强制得到一个唯一政治结论。
3. 日期类型：签署、批准、生效、移交、宣布、承认。时间精度为日／月／年／区间／未知；禁止把不确定日期伪装成1月1日的精确事实。
4. 几何来源：原地图、版本、出版日期、比例尺、投影、图幅页码；矢量化控制点与误差范围。
5. 证据：至少一份可追溯同期或权威文件，以及独立交叉核查资料；存在冲突时保留两种解释及取舍依据。
6. 审核状态：未核查→资料齐备→交叉核查→可发布；无证据不得自动转为已验证。
7. 数据许可：用途、署名、再分发限制；不同来源逐条保留许可，不默认能合并商业发布。
8. 几何验证：重叠、缝隙、拓扑有效性和跨日期变化；自动检查只是质量保障，不是历史真实性证明。

## 后续实施顺序

先确定主图是法理边界、实际控制，或两者并列。以德国和苏联两个用户点名专题完成一套端到端证据链，再推广到欧洲战后重组、全球去殖民化，最后补足全范围。2020—2026保留明确空白直至资料齐备。公开发布前还需处理现有数据的非商业许可。
